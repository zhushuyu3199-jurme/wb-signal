# 定盘

> **每个标的都有自己的锚。用锚定仓位，不定涨跌。**

每天两次（北京时间 12:00 / 22:00），把 6 个标的的「该买多少」算清楚，推到微信。

它不预测行情，只回答一个问题：**现在该拿多少仓位**。

---

## 为什么叫「定盘」

「定盘」有两层意思：一是秤上的**定盘星**，那是零刻度的位置，先有它才能称东西；二是交易里的**定盘价**，每天收市定一次价。

这个程序做的事正是这两件：给每个标的找到它的定盘星（锚），然后每天定两次盘。

**它不是行情软件，是仓位尺。**

各标的赚钱的底层逻辑不同，锚也不同，用同一套方法分析它们是最大的误区：


| 标的 | 代码 | 锚 | 核心指标 |
|---|---|---|---|
| 中证A500 | 512050 | 估值分位 | PE-TTM 十年分位（主）、PB 分位、ERP |
| 红利低波 | H30269 | 均线位置 + 估值分位 | 偏离250日线、股息率、PE/PB 分位（**10% 权重**）|
| 中证红利 | 000922 | 均线位置 + 估值分位 | 同上（**仅观察，不加权**）|
| 标普500 | 513500 | 溢价率 | IOPV 溢价、席勒 PE（含 8 年预期年化）、汇率 |
| 固收桶 | 511360 为主 | 资金面（不择时） | 7 日年化、GC007/Shibor1W、月末季末年末；**含南方金利定开(160128) + 易方达增强回报(110017)** |
| 黄金 | 518880 | 美国实际利率 | 10Y TIPS、美元指数（合成） |

推送：北京时间 **12:00**（午间快照）、**22:00**（完整版），周一至周五。

## 一、总开关：ERP 决定总仓位

```
ERP = 1 ÷ PE − 10年期国债收益率
```

| ERP | 权益目标 | 效果 |
|---|---|---|
| > 6% | 65% | 权益放大 1.18 倍，短融降到 30% |
| 4–6% | 55% | 基准 30/10/15/40/5 |
| 3–4% | 45% | 权益缩到 0.82 倍，短融升到 50% |
| < 3% | 40% | 权益缩到 0.73 倍，短融升到 55% |

其余五个指标只管结构，不管总量。

## 二、各自的阈值

### ① A500 — 估值分位

| PE 十年分位 | 动作 |
|---|---|
| < 20% | 全力加（3.0×） |
| 20–30% | 定投加倍（2.0×） |
| 30–70% | 正常（1.0×） |
| 70–80% | 减半（0.5×） |
| > 80% | 停投并减仓（0×） |

> 判据为 **背离度自动分段**（`A500["judge"]="auto"`）：
> 背离<15pp 取低；15–25pp 取低但降一档（等效分位+10pp）；>25pp 改取高并预警。
> 也可设为 `"min"`（永远取低）或 `"pe"`（只看 PE）。

### ② 港股通红利 — 股息率

| 股息率 | 动作 |
|---|---|
| ≥ 6.5% | 重仓加 |
| 5.0–6.5% | 持有 |
| 4.5–5.0% | 减半 |
| 4.0–4.5% | 减到三成 |
| < 4.0% | 清仓 |

程序同时显示**到手股息率（×0.8，扣 20% 红利税）**和**股息利差**。

> ⚠️ 利差基准是**美元 10Y**，不是中国 10Y —— 港币挂钩美元，用人民币利率给港币资产定价会虚高一倍。
> 数据源：FRED DGS10，失败时用 TIPS + 2.3pp 估算，再失败用兜底常量。
>
> 股息率超过 `HK_YIELD_FREEZE_DAYS`(90) 天未更新，程序**冻结判定**，不再输出档位。

### ③ 标普500 — 溢价率

| 溢价 | 动作 |
|---|---|
| < 1.5% | 场内可买 |
| 1.5–3% | 改场外申购 050025 |
| > 3% | 暂停买入 |
| > 8% | 极高，暂缓一切操作（个人无套利通道）|

### ④ 短融 — 资金面

7 日年化 ≥ 2.5% 可锁定；月末/季末/年末最后一周提示可多买；其余时间正常持有。

> 该 40% 不是纯短融：**短融ETF + 南方金利定开(160128) + 易方达增强回报(110017)**。
> 后两者是信用债/一级债基（含转债敞口），且有定开流动性锁 —— 真要用作权益弹药时可能取不出。

### ⑤ 黄金 — 实际利率

| 10Y TIPS | 判定 |
|---|---|
| < 0% | 大牛市环境 |
| >2% 且回撤>25% | **信号冲突，需人工判断** |
| 0–1% | 温和利好 |
| 1–2% | 中性 |
| > 2% | 压制金价 |

另加两条：实际利率下行 + 金价回撤 ≥15% → 可加；60 日涨幅 ≥30% → 减。

## 三、陷阱（推送里是精简版，这里是原文）

**A500**
- 分位低可能更低（2018 年到 20% 分位后又跌 30%）→ 只能分批
- A500 是 2024 年新指数，历史短 → 用沪深 300 分位代理
- 熊市末期 PE 虚高（盈利下滑、分母变小）→ 改看 PB
- 高估可以持续一年以上（2015 上半年）→ 别太早清仓

**港股通红利**
- 股息率反映过去 12 个月分红，盈利下滑时可能是假高息
- 港股通红利税 20%，5.6% 实际到手约 4.5%
- 汇率暗吃收益（港币挂美元），人民币升值时 ETF 人民币净值缩水
- 别在人人讨论红利时买入，那往往是阶段高点

**标普500**
- 溢价每天变，下单前必须看实时 IOPV，不能看昨天的
- 场外可能限购，大额买不进
- 美股估值中枢在抬升，用历史分位会一直「贵」
- 汇率双刃剑

**短融**
- 别为 0.5% 频繁交易，佣金吃掉收益
- 有信用风险（2020 年永煤 AAA 也违约）
- 它是权益的弹药库，不是收益来源

**黄金**
- 抗的是实际利率，不是通胀（2022 通胀 9% 金价反跌）
- 没有估值锚，只能用「相对利率吸引力」判断
- 5% 是保险不是投资
- 短期涨超 30% 要减

## 四、部署

上传 `github_deploy/` 里全部文件（**不要传 push_config.json**）：

```
run_daily.py  indicators.py  config.py  push_notify.py
combo_daily.py  ma250_monitor.py            ← 原四标的的信号引擎
hist_cs930955.json  hist_000922.json  nav_513300.json   ← 历史库，勿删
manual.json                                  ← 手动值（股息率）
.github/workflows/daily.yml
```

> `hist_*.json` / `nav_513300.json` 是均线计算的历史底座，脚本每天自动追加，
> 工作流最后一步会把变化提交回仓库。删了会导致信号失真。

Secret：`PUSHPLUS_TOKEN`。

```yaml
schedule:
  - cron: "0 4 * * 1-5"    # 北京 12:00
  - cron: "0 14 * * 1-5"   # 北京 22:00
```

> 旧的 combo_daily 工作流请删除，否则会重复推送。

### ⚠️ 已知问题：GitHub 定时任务会延迟数小时

自 2026-08-26 起，GitHub Actions 的 `schedule` 触发出现平台级延迟（社区报告 3–10 小时），
与仓库配置、套餐无关，`workflow_dispatch` 手动触发则瞬间执行。

**表现**：设 12:00/22:00，实际 03:48/17:31 才跑（延迟约 5.5 小时）。

**临时防线**：程序内置时间窗守卫（`config.SEND_WINDOW_*`），
午间只在 11:00–14:30、夜间只在 21:00–24:00 发送，越窗静默跳过，避免半夜推送。

**根治方案**：用外部定时器调 `workflow_dispatch`，绕过 GitHub 的 schedule 队列。见下方。

## 五、本地用法

```bash
python run_daily.py --dry --force              # 只看效果
python run_daily.py --dry --force --mode noon  # 强制午间版
python run_daily.py --set-hk-yield 5.6         # 录入股息率
python run_daily.py --set-shiller 36.2         # 手动覆盖席勒PE（一般不用）
python run_daily.py --force                    # 真推一次
```

手动值存 `manual.json`。**股息率超过 45 天未更新，会在三处同时提醒**：
数值后标「⚠️已 N 天未更新」、自动进入「今日动作」、夜间版单列「待维护」小节。
阈值改 `config.HK_YIELD_STALE_DAYS`。

## 六、口径与限制

| 指标 | 口径 | 限制 |
|---|---|---|
| A500 PE 分位 | 蛋卷 SH000510 → 无数据时降级 SH000300 | **当前是沪深300代理**，消息里标注 |
| 10Y 国债 | 东财中债 `EMM00166469` | 异常时在 config 填 `BOND_YIELD_OVERRIDE` |
| 港股通红利 股息率 | 手动 | 无免费实时接口 |
| 标普500 溢价 | 场内价 ÷ T-1 净值 | **不是 IOPV**，有 ±1–2% 噪声，下单前必须核实 |
| 标普500 席勒PE | **GuruFocus 自动抓取**（含 8 年预期年化） | 页面改版会失效，失败时回落到手动值 |
| 短融 DR007 | **GC007 + Shibor1W 双代理** | DR007 本身无公开接口；三者方向一致、水位接近 |
| TIPS | FRED DFII10 | 滞后 1–2 个交易日 |
| **美元指数** | 新浪外汇 6 个币对，按 ICE 官方公式合成 | 与 ICE 官方 DXY 一致，误差在小数点后两位 |
| **南向资金** | 东财沪深港通历史（MUTUAL_TYPE=006 南向合计） | 单位已换算为亿元；北向数据 2024-08 起不再披露 |

原则：取不到就显示「—」，文末列「数据异常」，绝不填假数字。

## 九、绕过 GitHub 定时延迟（推荐）

GitHub 的 `schedule` 不可靠，改用外部定时器直接触发 workflow：

### 1. 建一个 PAT
GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**
- Repository access：只选这个仓库
- Permissions → **Actions: Read and write**

### 2. 在 cron-job.org 建两个任务（免费）
| 项 | 值 |
|---|---|
| URL | `https://api.github.com/repos/<用户名>/<仓库名>/actions/workflows/daily.yml/dispatches` |
| Method | POST |
| Header 1 | `Authorization: Bearer <你的PAT>` |
| Header 2 | `Accept: application/vnd.github+json` |
| Body | `{"ref":"main"}` |
| 时间 | 每天 12:00 与 22:00（时区选 Asia/Shanghai）|

### 3. 保留 workflow 里的 schedule
留作备份。时间窗守卫会自动丢弃延迟过久的运行，不会重复推送。
